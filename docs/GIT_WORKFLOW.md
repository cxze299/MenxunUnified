# Git 仓库管理规范

## 分支

- `main`：稳定、可部署分支，不直接进行日常开发。
- `codex/*`：Codex 实施分支。
- `feature/*`：人工功能开发分支。
- `fix/*`：缺陷修复分支。

合并到 `main` 前必须通过后端测试、Go 静态检查、前端生产构建和 npm 安全审计。

## 提交

提交信息采用 `类型: 简短说明`：

- `feat:` 新功能
- `fix:` 缺陷修复
- `refactor:` 不改变行为的整理
- `test:` 测试
- `docs:` 文档
- `chore:` 构建或维护

一个提交只表达一个完整目的。禁止提交真实 `.env`、私钥、密码、数据库目录、用户上传资料、备份、`node_modules` 和 `dist`。

仓库使用 `.githooks` 中的版本化钩子。克隆后执行：

```bash
git config core.hooksPath .githooks
```

- `pre-commit`：检查敏感文件名、空白错误和超过 20 MB 的文件。
- `pre-push`：运行后端测试、Go vet、前端构建和 npm 安全审计。

不得使用 `--no-verify` 绕过钩子。

## 发布

每次 NAS 部署必须：

1. 工作区没有未提交修改。
2. 测试全部通过。
3. 从提交生成归档，不直接复制工作区。
4. 创建带注释标签，例如 `nas-v0.1.0`。
5. 在部署记录中保存提交 SHA、标签、时间和健康检查结果。

生产数据永远不纳入 Git。数据库、上传资料和备份均保存在 NAS 的 `data/` 目录。
